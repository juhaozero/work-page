# UI 改进方案 — Curated Terminal Index（现代终端窗）

> 目标：去掉廉价感与拥挤感，**坚持现代终端窗美学**，不换成通用作品集模板，也不回退老管 CRT。  
> 范围：首页为主（Hero → 精选 → 目录），详情页跟随后续。  
> 状态：立意已确认（2026-09-08）；**Phase A–C 核心项已落地**（精选升格 / 门户 / 详情 CTA / 关于 shell）  
> 日期：初稿 2026-09-07 · **同步 2026-09-08**

配套审阅：[ui-design-review.md](./ui-design-review.md)

---

## 1. 问题与目标

### 现状痛点

| 感受 | 根因 |
| --- | --- |
| 廉价 | 精选与目录同构；无封面证据；字号阶梯塌缩；品牌文案空心 |
| 拥挤 | 曾区块间距一视同仁；精选行信息可再分层 |
| 奇怪 | 两段都是「项目列表」，「一主一次」仍不够肉眼可见 |

### 成功标准

1. 首屏 3 秒能说清：这是谁的站、用来干什么。
2. 精选一眼重于目录；去掉精选后，目录仍可用。
3. 区块之间有明显换气；块内可保持终端密度。
4. 仍认得出：slate 终端底 + mint 强调 + JetBrains Mono + 方角 + `$` 命令行分区 + 在线状态语法 +（首页）红绿灯开机窗。

### 明确不做

- 不上圆角卡片墙 / 玻璃拟态 / 紫渐变 SaaS 风（开机 **窗框** 可圆角，内容区保持方角）
- 不引入第二套展示字体（继续 Mono）
- 不把目录改成双列作品卡（继续终端表）
- 不加霓虹 glow、glitch、扫描线、老管磷光回潮

## 2. 设计原则（本版）

| # | 原则 | 落地含义 |
| --- | --- | --- |
| P1 | **块间疏、块内密** | 区块 `py` / `gap` 加大；表行、链接行保持紧凑 |
| P2 | **一主一次** | 精选 = 策展舞台；目录 = `ls -l` 索引 |
| P3 | **证据优先于装饰** | 有 cover 上屏；无 cover 用 OG `/og/projects/{slug}.png` |
| P4 | **字号阶梯** | 门户主张 / 精选名 ≫ 表单元格 / label |
| P5 | **终端窗语法一致** | 左 inset 光边 hover、`[x]` 筛选、状态色、方角内容区 |

## 3. 信息架构（首页）

```text
┌─ Boot（首访/刷新）──────────────────────────┐
│  ● ● ●  github.com/…                         │  ← macOS 终端窗
│  > loading shell…                            │
└─────────────────────────────────────────────┘

┌─ Header（固定）─────────────────────────────┐
│ ◉ 在线 · Developer · 关于          语言 · 主题 │
└─────────────────────────────────────────────┘

┌─ A. Portal / Hero ──────────────────────────┐  ← 身份层（轻）
│  guest@dev:~$ ls ~/home                      │
│  [头像]                                      │
│  （可选）个人小项目索引                       │
│  GitHub / Email / Blog …                     │
└─────────────────────────────────────────────┘
         ↕ 大间距（约 4–5rem）

┌─ B. Featured（主舞台）──────────────────────┐  ← 视觉主层（重）
│  guest@dev:~$ cat ~/featured.list            │
│  FEATURED                                    │
│  ┌────────────────────────────────────────┐  │
│  │ [封面或 OG]  名称 + 描述 + tech + 状态  │  │
│  └────────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
         ↕ 大间距

┌─ C. Catalog（索引）─────────────────────────┐  ← 工具层（密）
│  guest@dev:~$ ls -l ~/projects               │
│  [x]全部 工具 …                              │
│  名称 | 分类 | 技术 | 状态                   │
└─────────────────────────────────────────────┘
```

**阅读节奏**：开机窗 → 身份 → 停顿 → 作品重点 → 停顿 → 全量索引。

## 4. 分区方案明细

### 4.1 Header

| 项 | 方案 |
| --- | --- |
| 布局 | 保持：在线 · 站名 · 关于 \| 语言 · 主题 |
| 小改 | `sm` 以下显示短站名或域名缩写 |
| 触控 | 主题/语言热区高度 ≥ 40–44px |

### 4.2 Portal / Hero

| 项 | 现状 | 方案 |
| --- | --- | --- |
| 标题 | 中文 `portal.title` 为空 | 可选填：「个人小项目索引」 |
| 头像 | 72px | 保持 |
| 链接行 | label + link | 保持终端通讯录 |
| 命令行 | `$ ls ~/home` + 打字 | 保持 |

**不放**：统计条、多 CTA、徽章堆叠。

### 4.3 Featured — 升格核心（仍待落地）

#### 结构（每项）

```text
┌─ terminal-card（surface 底）─────────────────────────┐
│  ┌──────────┐   名称（text-base / ~1.125rem，semibold）│
│  │  cover   │   描述 2 行（text-sm，muted）            │
│  │  或 OG   │   tech 一行（dim，· 分隔，最多 3）       │
│  │  媒体区  │   状态（右下或描述旁）          →        │
│  └──────────┘                                          │
└────────────────────────────────────────────────────────┘
```

#### 规则

| 规则 | 说明 |
| --- | --- |
| 封面 | 有 `cover` 用真实图；否则 OG `/og/projects/{slug}.png` |
| 去噪 | 不显示「项目 01」；分类交给目录 |
| Hover | 边框 → accent + 左侧 2px inset；**禁止**整卡 opacity |
| 区块标题 | `FEATURED` /「精选项目」用 `terminal-label` |

#### 与目录的差异（必须肉眼可见）

| | 精选 | 目录 |
| --- | --- | --- |
| 高度 | 约 88–112px / 卡 | 约 44–52px / 行 |
| 媒体 | 封面或 OG | 无（或极小） |
| 文案 | 名 + 2 行描述 + tech | 名 + 分类 + tech + 状态 |
| 背景 | `crt-surface` 卡片 | 透明表行 |

### 4.4 Catalog

| 项 | 方案 |
| --- | --- |
| 形态 | **保持终端表**（方案 A） |
| 筛选 | `[x]` 语法；热区 padding |
| Hover | 行 glow + inset（已有） |
| 移动端 | 上行名+状态 / 下行分类（已落地） |

### 4.5 间距与字号 Token（建议）

| Token | 值 | 用途 |
| --- | --- | --- |
| `--section-gap` | `4.5rem` / `sm: 5rem` | Hero↔精选↔目录 |
| `--featured-pad` | `1rem` | 精选卡内边距 |
| 门户标题 | `1.125–1.25rem` | Hero |
| 精选名 | `1.0625–1.125rem` | 高于表内名 |
| 表单元格 | `0.8125rem` | 保持 |
| Label | `0.6875rem` + tracking | 保持 |

### 4.6 运动（克制，2–3 个）

1. 开机窗入场 + 串行打字（`reduced-motion` 跳过）  
2. 分区命令打字 → 内容 stagger  
3. 卡/行 hover 150–200ms；主题 bg/color transition  

### 4.7 文案

| Key | 中文建议 | 英文建议 |
| --- | --- | --- |
| `portal.title` | 个人小项目索引（可选） | Personal tools index |
| `crt.bootLines` | 已改为 shell 语义（loading / source / cd / ready） | 同左 |

品牌名 `Developer` 是否改域名感 → **品牌决策**，见确认记录。

### 4.8 详情页（原则）

- 首屏：封面或 OG + 名 + 一句 + 主按钮「打开项目」权重大于次链  
- tech / lifecycle 保留元信息区  
- 与首页同族，避免详情变「另一套站」

## 10. Boot（首页开机 · 现行）

| # | 决定 |
| --- | --- |
| 形态 | macOS 风格终端窗入场 + 4 行串行打字 |
| 跳过 | 点击 / Esc / Enter / Space；前若干 ms 防误触 |
| 遮罩 | 全屏底色 = `--crt-bg`；窗用 surface / 红绿灯 titlebar |
| 文案 | `loading shell…` / `source ~/.profile…` / `cd ~/dev…` / `ready.` |
| 再访 | 首访或刷新主页播仪式；同会话返回可跳过（见 `crtBoot.ts`） |
| 减动效 | `prefers-reduced-motion` 跳过 |
| 详情 | 不加开机窗，保留 `cat` 命令行 |
| 项目区 | 门户后：`cat ~/featured.list` → 精选；再 `ls -l ~/projects` → 目录 |

实现：`CrtBootShield` + `crtBoot.ts` 事件串联 `HeroPortal` / `FeaturedProjects` / `ProjectCatalog`。
